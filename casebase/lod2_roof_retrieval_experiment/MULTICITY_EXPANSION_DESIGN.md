# LOD2 屋顶检索实验：多城市扩容设计

## 1. 目标与边界

本阶段把已在 Luxembourg 跑通的同源 G1/G2 指标与检索流程扩展到全部 19 个已有 LOD2 城市，建立数万级、城市构成相对均衡的跨城市候选库。主实验仍比较“只使用总体形态的 M1”与“在总体形态候选中加入屋顶信息重排的 M2”，不改动已经在 Luxembourg 冻结的指标定义、主权重和 Top-5 返回规则。

原生 LOD1 不是纳入条件。G1 始终从同一套 LOD2 建筑派生；同时拥有原生 LOD1 的城市只为后续附加一致性检查保留，不限制本阶段城市范围。

本阶段不使用 Isolation Forest。异常控制仅排除有明确几何、数据完整性或研究范围依据的街区，避免把真实但少见的形态误删。

## 2. 城市与数据源

数据库当前记录的 19 个 LOD2 城市为：Amsterdam、Berlin、Bern、Dresden、Hamburg、Hannover、Linz、Luxembourg、Lyon、Montreal、Munich、Namur、New York、Nuremberg、Prague、Rotterdam、Tallinn、Vienna 和 Zurich。现有记录估计这些城市共有约 79,550 个包含 LOD2 建筑的街区。

每个城市从以下只读源表取得数据：

- `block.<city>_blocks`：街区边界；
- `lod2.<city>_buildings_lod2`：建筑对象与二维轮廓；
- `lod2.<city>_building_surfaces_lod2`：RoofSurface 与 GroundSurface；
- `summary.city_name_map`：城市显示名和 `lod2_metric_srid`。

所有源 schema 均为只读。程序在运行前核验标准字段和测度 CRS；缺字段或无 `lod2_metric_srid` 的城市记录为失败，不通过猜测字段继续运行。动态表名只能从已经核验的城市目录构造，并必须通过小写字母数字标识符检查，不能接受 notebook 中任意输入的 SQL 名称。

## 3. 城市均衡与可复现随机抽样

每个城市最多保留 5,000 个最终可用街区；不足 5,000 个时保留该城市全部可用街区。这样既使用小城市的全部信息，又限制 Berlin、New York 等大城市对全局缩放和候选结果的支配。

抽样采用“先随机排序、再分批验证”的拒绝抽样流程：

1. 读取该城市所有至少匹配一栋 LOD2 建筑的候选街区 ID；
2. 使用全局种子 `20260909` 与城市名的 SHA-256 摘要生成稳定的城市专属种子；
3. 对候选 ID 做无放回随机排列；
4. 按 1,000 个街区一批读取建筑和表面、计算指标并执行硬筛；
5. 按随机顺序累计通过筛选的街区，达到 5,000 个后停止；城市耗尽时保留全部通过者。

因为筛选规则与排列顺序无关，随机排列中最先通过的 5,000 个街区等价于从全部可用街区中进行可复现的无放回随机抽样。每个城市保存候选总数、城市种子、已处理数、各原因排除数和最终街区 ID。

## 4. 硬筛规则及其含义

### 4.1 建筑级数据条件

沿用 Luxembourg 已实现的最低条件：建筑已匹配街区、二维轮廓面积为正、存在可计算的 RoofSurface 和 GroundSurface、G1 高度为正、屋顶三维面积和坡度可计算、屋顶高差比位于 `[0,1]`。数据库读取必须先保留选定街区内全部非空二维轮廓建筑，再以左联接或独立表面查询附加屋顶和地面；没有合格表面的建筑也要进入覆盖率分母。无法读取的个别表面记入原因码；建筑不满足必要指标时不参与街区指标。

### 4.2 街区级数据条件

以下条件用于排除不能可靠形成实验向量的街区：

- 街区面积和周长为有限正值；
- 至少有一栋可用建筑；
- 可用建筑底面积占全部已匹配建筑底面积的比例不低于 `0.80`；
- `0 < BCR <= 1.0`；其中 `BCR > 1` 表示建筑底面发生重叠、重复或归属异常；
- 紧凑度和伸长度位于 `(0,1]`；
- 街区屋顶平均坡度位于 `[0°,90°]`，屋顶高差比中位数位于 `[0,1]`，屋顶坡度离散度不小于 0；
- 冻结的 11 项 M1 指标和 3 项屋顶指标全部为有限值。

### 4.3 研究范围条件

主候选库额外要求 `BCR >= 0.02`。这不是数学有效性判断，而是研究范围控制：当道路围合单元中建筑覆盖不足 2% 时，该对象更可能代表公园、水体边缘、交通设施或超大空旷用地，不适合作为本次常规城市街区形态参照。此类街区单独记录为 `below_reference_bcr`，不与错误数据混称。

除上述条件外，不按面积上限、建筑数量上限、城市分位数或综合异常分数继续删除。罕见但合法的高层、单体大建筑、低密度或特殊屋顶街区仍可保留。

## 5. 指标与跨城市缩放

M1 固定为 Luxembourg 阶段确定的 11 项指标：`log_block_area`、`compactness`、`elongation`、`bcr`、`mean_h_g1`、`h_g1_cv`、`log_building_count`、`mean_footprint_area`、`footprint_area_cv`、`orientation_entropy`、`normalized_nn_distance`。不因多城市相关性结果重新删除指标；`volume_density` 继续只作为诊断字段。

M2 在完整 M1 上增加 `roof_mean_slope`、`roof_relief_ratio_median` 和 `building_roof_slope_sd`。各城市使用自身 `lod2_metric_srid` 计算几何量，合并后在全部最终街区上共同拟合中位数/IQR稳健缩放。共同缩放是跨城市直接计算距离的必要条件；同时输出逐城市分布，以识别来源或建模方式造成的系统偏移。

## 6. 检索规则

检索对象为合并后的跨城市候选库，查询自身按 `block_id` 排除，不限制候选与查询来自同一城市。

```text
D_general = sqrt(mean((M1_candidate_z - M1_query_z)^2))
D_roof    = sqrt(mean((roof_candidate_z - roof_query_z)^2))
D_M2      = 0.65 * D_general + 0.35 * D_roof
```

M1 先按 `D_general` 取最近 50 个总体形态候选并返回前 5 个。M2 只在相同的 50 个候选中按 `D_M2` 重排并返回前 5 个。结果保存查询城市、候选城市、是否同城、总体距离、屋顶距离、组合距离和原候选池排名。

首轮跨城市检索使用现有 20 个 Luxembourg 正式查询。若某查询未通过新的统一硬筛，只记录为不符合资格，不暗中替换。其目的首先是直接比较候选库从 500 扩大到数万后，参照案例是否更典型；各城市分层正式查询留到下一阶段建立。

## 7. 代码、数据库与输出隔离

新增文件：

- `03_multicity_pool_and_retrieval.ipynb`：可分步阅读、可恢复运行的主流程；
- `multicity_database.py`：城市目录核验、动态只读源表访问及多城市实验表写入；
- `multicity_pipeline.py`：稳定种子、批次选择、硬筛、抽样清单与跨城市汇总；
- 对应测试文件，覆盖随机性、筛选理由、数据库写入边界和跨城市检索元数据。

复用 `roof_geometry.py`、`block_metrics.py` 和 `retrieval.py` 中已经验证的方法。必要的通用化只增加城市字段和可扩展接口，不改变 Luxembourg 已冻结的数学定义。

数据库使用新 schema `exp_lod2_roof_multi`，至少包含：

- `sample_manifest`：候选、处理、排除及最终入样状态；
- `building_metrics`：最终入样街区所需的建筑级指标；
- `block_metrics`：多城市街区 M1/M2 指标与质量原因；
- `retrieval_results`：跨城市 M1/M2 检索结果。

实验 schema 按城市分区替换：重跑一个城市只删除和重写该城市的实验记录，不清空其他城市。每个城市作为独立事务提交，失败时回滚该城市。

文件输出写入 `outputs/multicity/`。每个城市分别保存指标与抽样清单，并生成合并街区表、城市统计、配置快照和跨城市检索结果。输出包含配置指纹；配置变化后不得把旧城市结果当作本轮断点继续使用。

## 8. 性能、失败处理与验证

- 建筑和表面继续使用数据库服务端游标流式读取；单次只处理一个城市的一批街区；
- 最近邻距离改用 `scipy.spatial.cKDTree`，避免大建筑街区中的平方级距离矩阵；
- 每批完成后释放建筑级中间对象；仅最终入样街区的建筑指标进入长期输出；
- 单城市失败不影响已经完成的城市，失败城市保留错误摘要并可单独重跑；
- notebook 默认不自动执行几十万至数百万表面的完整流程，由用户在现有 `urbanCode` 环境中运行；代码开发阶段只运行合成数据和数据库只读接口测试。

验证至少覆盖：同一城市种子多次运行得到相同顺序、不同城市种子不同；随机顺序中最先通过的 5,000 个被保留；各项排除原因互相可解释；源 schema 无 DDL/DML；实验写入不能越过 `exp_lod2_roof_multi`；跨城市检索正确记录候选城市且仍排除查询自身。

## 9. 本阶段完成标准

1. 新 notebook 能逐城市盘点、分批处理、硬筛并形成最多每城 5,000 个的最终样本；
2. 所有随机种子、样本 ID、排除原因、城市数量和配置指纹可追溯；
3. 19 个城市能够独立运行和恢复，单城字段问题不会破坏其他城市结果；
4. 合并候选库能够对符合资格的 Luxembourg 正式查询运行跨城市 M1/M2 Top-5；
5. 新增单元测试与既有测试全部通过；
6. 本阶段只在设计里程碑和完整实现里程碑提交，不产生逐小步骤提交。
