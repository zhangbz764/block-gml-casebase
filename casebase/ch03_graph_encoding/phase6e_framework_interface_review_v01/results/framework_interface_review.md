## 1 两套框架实际生成链路

官方main提交已通过GitHub API核实：GlobalMapper为`24c8891c5988bf6459cce0e357fd45eebd621cec`（2023-10-10）；HouseDiffusion为`083c9c5f7815e36e2685bd58bce7ea68946e2c4b`（2026-03-21）。以下源码定位均固定这两个提交，不使用浮动main作为最终证据。访问日期均为2026-10-15；逐文件URL见source_inventory.csv。

### 1.1 GlobalMapper

| 阶段 | 已核实实现及含义 |
|---|---|
| 输入／规范化 | `example_canonical_transform.warp_bldg_by_midaxis`由原轮廓和场地中轴得到规范化中心、尺寸及排序；`urban_dataset.graph2vector_processed`读取存在性／merge、中心、尺寸、shape、iou和预处理图的edge_index。不是从103项自动识别布局。 |
| 条件 | 默认配置选`AttentionBlockGenerator_independent_cnn`；`UrbanGraphDataset.get`将64×64场地mask与尺度通道叠加，CNN产生128维条件。训练分支不是把FAR、限高或案例关系作为现成输入。 |
| 学习／生成 | 编码器读取真实位置／尺寸、形状、存在性与槽位one-hot，经图消息传递和全局池化得到512维VAE潜变量；`decode(z,block_condition,edge_index)`展开120槽位，沿槽位图传播，输出存在性、位置、尺寸、6维形状logits及iou。节点数由存在性输出决定；没有高度或独立旋转角输出。 |
| 几何输出 | `test.py`默认`is_reconstruct=True`，先编码真值再重构；非重构分支用保存的潜变量均值／标准差采样。公开测试写出gpickle槽位图；`geo_utils.inverse_warp_bldg_by_midaxis`可恢复按中轴方向旋转的矩形。不能把测试脚本当作完整任意轮廓合成入口。 |

证据：[数据读取L113](https://github.com/Arking1995/GlobalMapper/blob/24c8891c5988bf6459cce0e357fd45eebd621cec/urban_dataset.py#L113)、[默认模型选择L151](https://github.com/Arking1995/GlobalMapper/blob/24c8891c5988bf6459cce0e357fd45eebd621cec/train.py#L151)、[条件解码L466及CNN L522](https://github.com/Arking1995/GlobalMapper/blob/24c8891c5988bf6459cce0e357fd45eebd621cec/model.py#L466)、[测试L35及L236](https://github.com/Arking1995/GlobalMapper/blob/24c8891c5988bf6459cce0e357fd45eebd621cec/test.py#L35)、[中轴逆变换L204](https://github.com/Arking1995/GlobalMapper/blob/24c8891c5988bf6459cce0e357fd45eebd621cec/geo_utils.py#L204)。

图的关键：`graph_util.sparse_generate_graph_from_ftsarray`明确创建`nx.grid_2d_graph(4,30)`。解码器接收的edge_index用于固定槽位消息传递，不是建筑轮廓tessellation邻接；数据加载虽有通用取边函数，实际向模型传的不是12项连续edge_attr。merge作为输入字段出现，但公开输出函数将其置0，不能据此宣称已学习接触组合体量。yaml虽有height_weight，实际模型返回和训练损失没有高度项；图写出函数未传高度时填0，不能把配置键当功能实现。

论文与代码须分开：[论文v1 §3.1—3.3](https://arxiv.org/html/2307.09693v1#S3)描述四种基本轮廓及占用率的参数化合成／修正；所读代码是6维shape分类，但未提供清晰的类别字典、完整轮廓拟合／合成调用及从任意原始布局到4行槽位的完整分配管道。中轴示例有位置排序，结尾仅提示构建图，不等于交付槽位分配器。初查材料的“五类形状”不作为已核实接口。完整布局的组织来自中轴规范化、槽位结构、学习分布和几何恢复共同作用，不是仅GAT的结果。

### 1.2 HouseDiffusion

| 阶段 | 已核实实现及含义 |
|---|---|
| 输入 | `scripts/image_train.py`→`load_rplanhg_data`→`RPlanhgDataset`。原始图由房间／门及门连接构成；Transformer token是每个多边形的角点。点坐标由256画布映到[-1,1]，附25维类型、32维角点ID、32维组件ID和环连接。 |
| 数量／条件 | 组件集合来自输入图，不由存在性头生成；eval从训练类型的角点数分布采样每组件角点数。原加载器总点上限100，组件／角点ID也有容量限制。self_mask按组件分组，door_mask按连接，gen_mask覆盖所有有效点，均为0／1可见性；没有连续边属性接口。 |
| 去噪／目标 | 4层、4头、512通道Transformer处理带噪角点；每层并行组件内、关系和全局注意力。`training_losses`为padding屏蔽后的连续噪声MSE和离散坐标位MSE，离散损失在t<10启用；采样在t<32切换离散预测。不是按建筑间距、FAR或限高优化。 |
| 采样／输出 | `image_sample.main`传条件及形状，不把目标坐标作为采样初值；`p_sample_loop_progressive`从噪声生成，使用syn_条件。`save_samples`按组件ID拼接闭环并输出图像／SVG；朝向隐含在角点中。没有街区新边界条件支路、建筑高度头或开敞空间任务。 |

证据：[加载器L85及L189](https://github.com/aminshabani/house_diffusion/blob/083c9c5f7815e36e2685bd58bce7ea68946e2c4b/house_diffusion/rplanhg_datasets.py#L85)、[条件与掩码L317](https://github.com/aminshabani/house_diffusion/blob/083c9c5f7815e36e2685bd58bce7ea68946e2c4b/house_diffusion/rplanhg_datasets.py#L317)、[注意力L46和forward L215](https://github.com/aminshabani/house_diffusion/blob/083c9c5f7815e36e2685bd58bce7ea68946e2c4b/house_diffusion/transformer.py#L46)、[损失L787](https://github.com/aminshabani/house_diffusion/blob/083c9c5f7815e36e2685bd58bce7ea68946e2c4b/house_diffusion/gaussian_diffusion.py#L787)、[采样L333](https://github.com/aminshabani/house_diffusion/blob/083c9c5f7815e36e2685bd58bce7ea68946e2c4b/scripts/image_sample.py#L333)。[论文v1 §4](https://arxiv.org/html/2211.13287v1#S4)解释房间／门闭环与连续／离散去噪；原公开实现未显示自动把建筑邻接翻译成室内门连接的合法机制。

建筑适配不是room→building改名：街区内建筑之间应允许空地而非室内共享墙先验；背景可隐式保留，但须显式输入新场地和约束越界／交叠，不能把场地边界简单当另一房间。接触体量需要组合身份／共享边表示，高度需独立输出。孔洞、多部件和变长角点需明确编码，不能只取最大外环且不披露。新增连续关系可作为注意力score偏置或独立边消息，但这是改造；原二值mask不能表达希望保持多大间距。模型也不是硬约束必定铺满场地，主要迁移风险是室内训练先验、条件和表示不同。

## 2 我们的编码如何进入实际生成

下表均是**拟议接口，不是本轮已实现能力**。保留v0.3.2资产原样，做任务级派生，不要求103项全部输入。

| 已有信息 | 原模型需要什么 | 拟议接口及去向 | 保留／丢失 | 改动量 |
|---|---|---|---|---|
| A的轮廓、形状、面积、height_m及有效性mask | GM要规范化中心／尺寸／shape／iou；HD要闭环角点和组件类别 | GM新增参照编码器读取A节点构成与缺失标记，输出逐节点记忆H_A；原轮廓用于参照特征／监督几何转译，非直接搬回输出 | 允许明确读取A几何；首轮矩形输出不能保孔洞和细节，不能称无几何解码 | 中；完整轮廓恢复另有缺口 |
| tessellation端点及12项连续边值 | GM只有槽位edge_index；HD只有二值连接mask | GM在独立参照GNN中消费edge_attr+missing，经cross-attention进入解码槽位；HD若选用须改注意力score／消息 | 原关系不重写成槽位边；全套12字段可沿现有适配器传递，但哪些启用须后续选定；角度／尺度需规范化，弱边标记不自动删除 | GM中；HD中到大 |
| A的原边界、规模与开发状态 | GM中轴规范化／场地mask尺度；HD固定画布 | 将A的尺度／原条件标为参照上下文，不混同设计条件；绝对位置可从首轮关系支路去除，仍承认相对关系含几何信息 | 保留源几何可追溯；不强制复刻A原场地位置 | 中 |
| 设计者的新边界、FAR、限高 | GM原生只有场地mask／尺度；HD无独立街区条件支路 | GM保留新边界CNN，增加明确FAR／限高向量，直接送decoder，不先与A属性相平均 | 规划要求与A原强度分开；硬符合要输出后核验，条件输入本身不保证达标 | 中 |
| 接触／组合体量 | GM merge不是有效生成组合头；HD门关系不是建筑组合 | 先辨明共享线、点接触、叠置和物理组合的差别；必要时派生group/part接口、组级布局与内部关系；不在本轮全库合并 | 现有轮廓／源ID可辅助，但没有可靠物理组身份；不能默认全部独立或把接触全部union | 当前缺口；纳入则大 |
| 建筑数量、朝向与几何复杂度 | GM120槽位＋存在性，中轴决定朝向；HD组件数给定、角点数采样 | 首轮保留GM槽位存在性和中轴几何，输出新ID，不固定与A逐栋对应；复杂轮廓与自由角度暂不宣称支持 | 数量可变但受容量／行组织限制；细部朝向与组合可能丢失 | 保留骨架较小；换组织大 |
| 高度及体量 | 两者均无本项目所需高度生成／规划接口 | 后续GM每槽位增高度头并与新限高条件关联；由最终轮廓×高度／3m计算等效FAR | 只生成LoD1体量代理；不是源层数真值或完整建筑设计 | 中，不能单独当创新 |
| block总体指标、ID、城市及cell | 多数不是原模型输入 | ID仅关联；部分构成描述供参照编码，其余评价；cell暂不作为地籍地块／额外生成节点 | 不把城市名／编号作为形态；不强塞全部字段 | 小 |

**GM两种改变的代价：** 保留120槽位、slot one-hot和网格GAT，新增独立H_A条件与新规划向量，是本比较中较小的结构改造；仍需新条件学习、几何适配和高度头，不能称只换数据。把解码图换成A的真实邻接，则固定槽位展开、存在性、生成数量、节点对应、顺序和新方案拓扑都要重设，接近重写生成组织，不是简单换edge_index。本轮明确不推荐后一种。

拟议信息流：`A轮廓／构成＋原邻接／连续边值 → 参照GNN的H_A；新边界→原CNN，新FAR／限高→新条件支路；随机z＋slot query＋新条件，经对H_A的可调强度cross-attention→原网格decoder→新布局／高度→几何恢复和独立核验`。H_A不只池化成另一个固定32维向量；继承强度α调节的是参照注入，不是两个潜向量的线性插值。关系信息进入生成过程，而非最后才打一个相似度分。

### 一例静态接口与几何边界

原Graph只读Boston `P4B_US_BO_000046`，路径`phase4b_full_graph_batches_v032/results/dataset/graphs/part_10/Boston/chunk_0001/P4B_US_BO_000046.graph.json.gz`。实际v0.3.2且validation.passed，9节点／16边，原数=编码数=9；node含WKT／height_m，边含12项关系及mask。一条边轮廓间距9.77451m、块归一化间距0.120207、方向相似度0.999999，拟进入H_A而不是生成槽位邻接。9个输入节点不意味着必须输出同样9栋。

参照现有6C适配器可沿用12维边值、双向端点及反向边时交换connection_axis_alignment_i/j，标准化带缺失mask；**不能直接把它的bbox/L节点位置当GM中轴坐标**。A参照记忆无需先硬绑到目标槽位；训练目标布局的槽位分配必须另建明确映射，避免排序悄悄丢掉源关系。

只回读6D原有三例缓存：Bologna／Boston／Berlin分别13／9／15节点，外环角点93／61／107。原HD的100点加载器会排掉Berlin，不能无声简化或扩大后仍称原版。按米制距离≤1e-6、共享线长>1e-6检查，Bologna有12对共享边，Berlin有14对及1对点接触／近接触，Boston无接触；三例未见正面积交叠超过1e-6m²。这只是几何接触，不证明物理同栋／裙房身份，也不授权全部合并。首轮受限对象应优先无此歧义者，Bologna／Berlin暂不作为可自由拆动的独栋训练示例。

### 没有真实A→B配对时怎样学习

可以从现有实际布局B学习`p(布局|场地、已知开发条件)`，B几何进入监督目标及训练后验q，不作为推理时的未知目标输入。参照支路可先以B的选定关系／构成作为自参照、随机屏蔽部分信息训练，或用明确的人工扰动构造几何适应任务；这分别支持条件分布学习、自参照恢复／抗扰动，不是现实改造配对。换A、换场地、指定库中少见FAR的组合仍可能出分布；不能据重构就声称学会了真实改造，单靠邻近案例匹配也不能制造“正确B”。

应同时保留无参照／参照dropout路径，避免生成器只学复制或完全忽略H_A；未来用同新条件、同随机z改变参照或α，观察输出是否有可解释的继承与非平凡变化。具体训练样本、划分、epoch和预算本次不固定。推理时只允许已知A几何与新场地，不读取目标B完整坐标／轮廓；补全或自重构结果须如实命名。

训练条件必须与生成对象口径一致：原block指标基于排除前集合，而且原FAR使用层数，不同于连续高度／3m代理。即使本例无节点排除，原Graph far=0.197332，而6D缓存的等效FAR=0.194092。若新模型输出高度，应在任务级目标上派生统一口径条件，不能混用旧FAR标签，也不覆盖原Graph。新FAR／限高输入、训练约束和最终几何评价三者需要统一，不能只挑达标图。

## 3 推荐与首次运行范围

### 为什么只选GlobalMapper骨架

| 判断面 | GlobalMapper | HouseDiffusion |
|---|---|---|
| 对象／组织 | 建筑街区＋中轴行组织，较直接；不覆盖所有组合体量 | 房间／门闭环，跨域更大，空地与组合需重设 |
| 真关系接入 | 无原生连续边接口；独立参照记忆可保留原解码组织 | 条件直接进多层注意力，位置明确；连续属性仍需改造 |
| 输出／完整度 | 槽位存在性和中轴矩形链可读，完整轮廓合成与槽位预处理有缺口 | 角点生成链可读，但100点、类别、环和量化体系限制明显 |
| 改动与硬件 | 结构改造相对可控但不是小脚本；旧PyG／几何依赖、授权和4070预算待定 | 需改加载器、关系语义、场地、高度、开敞空间和容量；同样未测显存 |
| 研究区分 | 组内近邻多，不能把复现＋高度／微调／潜插值当贡献 | 不因换扩散就有创新；室内→街区本身也不证明组织可控 |

明确选择GM是以“先形成合理建筑布局基础”为优先，不是判断其真实关系机制更强。保留中轴／槽位与GAT／CVAE生成机制；改数据适配和新条件入口、增H_A参照注入及高度头。完整原轮廓恢复不在首次目标内；若研究者要求第一步就无损轮廓／组合体量生成，则本推荐的受限首轮不满足要求，不能悄悄升级范围。

### 下一次首次运行做什么
